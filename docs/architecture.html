Executive Summary

A two-tier demo application. A Vue 3 single-page app talks over HTTP/JSON to a Python FastAPI service. There is no database. The backend loads seven JSON files into memory at startup and filters them in Python on every request. All state is read-only at runtime, and restarting the server reloads the original data.

Data Flow

This example follows one filter change on the Overview page.

  1. User selects a filter in FilterBar.vue, for example Location = Tokyo.
  2. Shared state updates. useFilters.js holds module-level refs, so every view sees the same values.
  3. The view reacts. A watcher in the active view calls getCurrentFilters(), which maps the period to month and the location to warehouse.
  4. The API client builds the request. api.js adds only the non-'all' values as query params, for example GET /api/orders?warehouse=Tokyo.
  5. The backend filters in memory. apply_filters() then filter_by_month() run over the lists loaded at startup.
  6. Pydantic validates the response against the response_model and serialises it to JSON.
  7. The view recomputes. The response is stored in refs (allOrders, inventoryItems). Computed properties derive the KPIs, chart data and tables, and useI18n applies the translations and currency.

Composables (shared state)

  • useFilters: the four global filters, shared as module-level singleton refs
  • useI18n: en and ja dictionaries, locale saved in localStorage, currency follows locale (USD or JPY)
  • useAuth: mock current user (no real authentication)

  • FilterBar, LanguageSwitcher, ProfileMenu
  • Detail modals: Inventory, Product, Backlog, Cost, Profile
  • TasksModal

Observations

  • Frontend ahead of backend. api.js calls the tasks and purchase-order endpoints, but the backend has neither. As a result, "Failed to load tasks" (404) appears on every page load. purchase_orders.json is loaded only to compute the backlog flag.
  • Missing component. Dashboard.vue uses PurchaseOrderModal, but that component does not exist in components/. This breaks the "Create PO" action.
  • Read-only data. Nothing persists. Every endpoint returns data from module-level lists loaded once at import time.
  • Demo-grade security. No authentication, CORS open to all origins, no rate limiting. Suitable for local development only.
  • Hard-coded configuration. The API base URL (http://localhost:8001/api) and the 2025 quarter map are fixed in code.
